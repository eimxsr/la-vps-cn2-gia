## 线路选择的实际差异

CN2 GIA、AS9929、CMIN2这些线路名词听着玄乎，落到实际使用就是晚高峰（北京时间20:00-23:00）能不能稳定连接、延迟会不会飙到300ms+的区别。

**CN2 GIA**（中国电信精品网）是电信的最优质国际线路，去程和回程都走独立光缆，不和普通用户挤带宽。从洛杉矶到国内电信骨干网的路由跳数通常只有10-12跳，延迟可以稳定在120-140ms。电信宽带用户体验最直接，但联通和移动用户通过CN2 GIA也能受益，因为回国这一段避开了拥堵的骨干网。

**AS9929**（联通精品网，也叫CUII）是联通的高端线路，比普通AS4837延迟低、丢包少。联通宽带用户走这条线就是"本家对本家"，晚高峰优势明显。从实际使用反馈看，联通用户访问走9929的洛杉矶VPS，延迟通常比走CN2 GIA还低10-20ms，能稳定在110-130ms区间。

**CMIN2/CMI**是移动的精品网络。移动宽带用户数量大、普通线路容易拥堵，CMIN2相当于给移动用户开了专用通道。移动用户访问普通国际线路的洛杉矶VPS，晚高峰延迟经常飙到200ms甚至丢包，走CMIN2可以控制在140-160ms。

ZoroCloud的US-CNC系列把三家运营商的精品网都覆盖了，适合不确定用户是哪家宽带的场景，比如面向国内的SaaS服务、公开访问的网站。如果你自己用或者明确知道主要用户是联通宽带，US-9929系列够用且便宜20元。电信和移动用户如果预算够，US-CNC的CN2 GIA+CMIN2组合会更稳定。

用测试IP可以提前检查线路质量。在本地命令行运行`ping 38.34.13.1`（US-9929系列）或`mtr 72.249.202.166`（US-CNC系列），看看延迟稳定在多少、路由经过哪些节点、有没有丢包。不同地区、不同时段结果会有差异，最好在你常用的时间段测几次，尤其是晚高峰。

## 原生IP和住宅IP的区别

**原生IP**指的是IP的归属地和服务器实际位置一致，查询IP数据库时显示的国家/城市是对的。Netflix、Disney+、ChatGPT这些平台会检测IP归属，非原生IP（比如广播IP、数据中心IP被标记为代理）会被拒绝访问。

ZoroCloud的9929/CMIN2双ISP系列和BGP双ISP系列都标注了"原生双ISP"，意思是IP同时被两个ISP（Internet Service Provider）数据库认可，而且归属地是真的在洛杉矶。这类IP可以解锁美区的流媒体，价格34.8元/月起，比专门的住宅IP便宜很多。

**住宅IP**（Residential IP）更进一步，IP来自真实的家庭宽带网络（比如ATT、Verizon这种美国本土电信运营商），平台检测时会认为这是普通家庭用户。TikTok、Facebook这些社交平台对IP归属特别敏感，用数据中心IP注册或登录容易被风控，住宅IP能大幅降低封号风险。

ZoroCloud的US-Astra系列（ATT住宅IP）最低188元/月，是普通线路的4-5倍价格。官网显示暂时售罄，说明这类IP供应有限。如果确实需要住宅IP，可以看看竞品：AkileCloud的洛杉矶家宽系列49.99元/月起（1核2GB/1000Mbps带宽），TmhHost的GTT住宅IP 50元/月起（联通4837优化）。但这些竞品要么流量限制更严（AkileCloud超流量限速至10Mbps），要么带宽不如ZoroCloud的100Mbps稳定。

## 按使用场景选套餐

**个人博客、小型网站（月访问量1万以下）**

假设平均每个页面加载300KB（包括HTML、CSS、图片），1万访问量≈3GB流量。考虑到爬虫、RSS订阅、图片重复加载等额外消耗，实际可能需要5-8GB/月。US-9929-Mini（39元/月，500GB流量）或者9929/CMIN2双ISP最低档（34.8元/月，400GB流量）的流量足够用一年。

100Mbps带宽意味着峰值下载速度12.5MB/s，应付几十个并发访问没问题。如果用WordPress，建议装LiteSpeed Cache或者WP Super Cache减少动态请求，再配合CDN把图片缓存到边缘节点，能把流量消耗降到更低。

**需要跑数据库或多个服务**

1GB内存运行WordPress+MySQL+Redis会比较紧张。MySQL默认就要占用200-400MB内存，PHP-FPM开5-10个worker又是100-200MB，加上系统进程和文件缓存，1GB内存基本满载。访问量稍微上来一点，系统就会开始swap（把内存数据交换到硬盘），网站响应速度明显变慢。

US-CNC-Pro（99元/月，2核4GB/40GB NVMe/2TB流量）是性价比分界点。4GB内存能给MySQL分配1GB InnoDB缓冲池、PHP-FPM开15-20个worker，还有余量给系统文件缓存用。NVMe的随机读写IOPS是SSD的3-5倍，数据库查询索引、写入日志的速度都会快不少。

如果需要同时跑多个服务（比如主站+测试站+Jenkins+私有Git），或者要编译代码（比如Go、Rust项目），2核CPU也比1核流畅很多，不会因为编译任务把整个系统卡住。

**弱密码政策会导致删机无退款**

## 购买前最后确认两件事

**用测试IP检查实际延迟**

US-9929系列的测试IP是38.34.13.1，US-CNC系列是72.249.202.166，US-CERA系列是154.13.5.138。在本地命令行运行`ping 38.34.13.1`或者`mtr 38.34.13.1`，看看延迟稳定在多少、有没有丢包、路由经过哪些节点。

不同地区、不同运营商、不同时段结果会有差异，最好在你常用的时间段测几次，尤其是晚高峰（20:00-23:00）。如果晚高峰延迟飙到200ms+或者丢包超过5%，说明线路可能不适合你的网络环境，可以换个系列测试或者考虑其他商家。

Windows系统用`ping -n 100 38.34.13.1`测100次，看平均延迟和丢包率。Linux和macOS用`mtr -c 100 38.34.13.1`，能看到每一跳的延迟和丢包情况，更容易判断问题出在哪个节点。

**确认流量够不够用**

500GB流量如果只是SSH登录、跑脚本、建小站点够用，但如果要传输大文件、做视频站、挂BT/PT就不够了。算一下自己一个月大概要跑多少流量：

- 纯文字博客（每页100KB）：10万访问量≈10GB流量
- 图片为主的站点（每页500KB）：10万访问量≈50GB流量
- 视频站点/文件下载：每个100MB视频被下载100次=10GB流量

还要考虑额外消耗：爬虫抓取、API调用、系统更新、备份传输等，通常会在预估流量基础上再乘1.5-2倍。宁可买高一档也别卡在月底流量不够的尴尬境地。如果预算有限，可以配合CDN使用（比如Cloudflare免费版），把静态文件缓存到边缘节点，能大幅降低源站流量消耗。
